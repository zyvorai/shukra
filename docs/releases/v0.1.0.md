# Shukra 0.1.0

This note describes the first packaged release. It is not a tag. Tag `v0.1.0` only when you mean to publish the artifacts.

## Support

Guest traffic, isolation and egress policy require **Linux 6.6 or newer**, because they attach with TCX. There is no classic tc datapath. A kernel older than 6.6 keeps the host probes and reports `tap` detached. That is a failed attach, not a supported mode.

| What | Requirement |
|---|---|
| Host probes (`kvm`, `sched`, `block`, `net`, `vmm`) | Linux 5.8+ |
| `drops` | Linux 5.17+ |
| Guest tap, isolation, egress policy | Linux 6.6+ (TCX) and `CAP_NET_ADMIN` |

| Level | Means |
|---|---|
| Tested | The lab hypervisor is Linux 6.8. `scripts/test-tap.sh` runs on the GitHub runner that builds the guest workflow, which is 6.6 or newer. Host probes are exercised by `go test` and by that hypervisor. |
| Expected | Another 6.6+ kernel of the same architecture, through CO-RE. The objects are built on the release runner for that architecture. |
| Unsupported | Guest traffic, isolation and egress policy before Linux 6.6. There is no classic tc datapath. The container image is not the way to load eBPF. |

A red `scripts/test-tap.sh` on an older kernel means guest traffic is unsupported there. Do not treat 5.14 or 5.15 as a release gate for the tap program.

A new tap is attached from a netlink notification, and its saved policy is pushed before the daemon reports that tap as covered. The two-second scan remains. `-quarantine-uncovered` is off: an enforcing VM with a live tap and no program is a `tap-uncovered` detection, not a blackhole.

## Upgrade

Hosts that reached `0.0.0.0:30970` over plain HTTP stop doing that. The unit listens on `127.0.0.1:30970`. To keep the old bind, set both `-listen 0.0.0.0:30970` and `-allow-insecure-http` in `SHUKRA_EXTRA_ARGS`, or terminate TLS in front of loopback. A packaged install keeps the random key in `/etc/shukra`. `/etc/shukra` and `/var/lib/shukra` are not removed.

## Container

The image is not the hypervisor install. systemd on the host is. The image's default command listens on `127.0.0.1:30970`, so `docker run -p 30970:30970` alone does not publish the API. Replace the command.

Behind TLS, mount a certificate and listen on every interface:

```bash
docker run --rm -p 30970:30970 \
  -v /path/certs:/certs:ro shukra:local \
  -listen 0.0.0.0:30970 -tls-cert /certs/tls.crt -tls-key /certs/tls.key \
  -web /usr/share/shukra/web
```

Plain HTTP on `0.0.0.0` also needs `-allow-insecure-http`, and the container must sit behind a TLS proxy. Caddy, NGINX and HAProxy examples are in [Deploy a hypervisor](../tutorials/03-deploy.md).

## Rollback

Install the previous `.deb` with `dpkg -i`. Configuration and state stay. `shukrad -detach-all` removes pinned TCX links.

## Known limitations

- No guest agent, and no view of which process inside the guest.
- VLAN tags, IPv6 extension headers, ICMP events, and memory pressure are not measured.
- A tap that is not in the host namespace, and that nothing maps to one, has no guest traffic.
- Responses only isolate, and only when you turn them on. An egress policy is not a firewall.
- Enforcement across a restart needs `/sys/fs/bpf`.
- Percentiles come from log2 buckets and can read up to 2x high.
- There is no fleet controller, no migration timeline, and no language model in the daemon.
- Kernels older than 6.6 do not get guest traffic. Host probes on 5.8+ are the whole of what those kernels run.
